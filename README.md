# A 股人工交易辅助工具

独立的 Python 应用。后台自动维护日线、盘前选出最多 5 只股票、轮询腾讯行情并在故障时尝试新浪。网页提供实盘、虚拟盘-稳健、虚拟盘-激进及行情与系统页面。两套虚拟盘独立记账，实盘由用户选择策略。**不会向券商自动下单。**

当前完整运行规则见 [CURRENT_STRATEGY.md](CURRENT_STRATEGY.md)，机器配置见 [strategy.json](strategy.json)。次日买入折扣使用信号日锁定的 `2.25% + 0.25 × ATR14／复权收盘价`，再作用于信号日原始收盘价并向下取整到分。源码只依赖本目录；本地运行默认读取工作空间现有的市场数据库。服务器部署时可新建数据库并重新采集历史行情。

单台 Linux 服务器的部署、数据初始化和更新步骤见 [deploy/README.md](deploy/README.md)。服务器直接运行 Python 虚拟环境中的服务，使用 HTTP 80 端口提供网页和同域 API。

## 运行环境

- Python 3.11 或更高版本；已在本机 Python 3.13.5 验证。
- Windows、Linux 均可运行；SQLite 状态库和 DuckDB 市场库必须在本机文件系统，不要直接置于共享网盘。
- 安装依赖：

~~~powershell
cd E:\workspace-lulumoon\trading_assistant_app
python -m pip install -r requirements.txt
~~~

## 首次启动

~~~powershell
python run.py init
python run.py worker
~~~

另开一个终端运行网页：

~~~powershell
cd E:\workspace-lulumoon\trading_assistant_app
python run.py web
~~~

浏览器打开 http://127.0.0.1:8765 。手机专用虚拟盘页面位于 http://127.0.0.1:8765/m ，仅展示稳健盘和激进盘的概览、操作记录、历史持仓；部署到服务器后，将地址中的主机名换成服务器地址即可。后台必须持续运行，关闭网页不会停止采集。Windows 可将这两条命令分别配置为任务计划程序的登录启动任务，并启用失败重启；网页服务只监听本机。

休市日启动时，后台会检查最近一个已完成交易日；若日线未补齐，会自动追赶并在终端打印批次进度。已补齐时会打印下一交易日并保持等待。可在另一个终端执行 python run.py status 查看 worker_heartbeat 和 catchup 状态；网页首页也会显示后台心跳。若修改源码，需重启后台进程才能使用新代码。新买入公式只用于重启后首次**尚未发布**的盘前名单；已发布名单和持仓沿用数据库中冻结的价格。

**默认启用买卖提醒与虚拟成交记录**：系统同步数据、生成名单、记录报价样本，并在有效报价满足条件时生成提醒与虚拟交易；券商委托和实际成交仍由人工完成。需要暂时只观察行情时，在后台进程的环境中设置 `TA_OBSERVE_ONLY=1` 并重启后台。网页“行情验收”展示最近 5 天的轮询覆盖率和有效源时间戳数量；免费报价仍需与券商终端抽查。不要把“轮询间隔 3 秒”理解为来源每 3 秒必有新价格。

盘中报价若连续 3 次轮询仍有缺报，系统发出行情故障提醒；完整报价恢复后自动把该提醒标为“已恢复”。开盘瞬间的短暂缺报仍保留在轮询记录中，但不会立即发出故障提醒。提醒时间在网页按北京时间显示。

## 配置

| 环境变量 | 默认 | 用途 |
| --- | --- | --- |
| TA_MARKET_DB | 上级目录 data/market_full.duckdb | 历史日线与分钟线 DuckDB 的绝对路径 |
| TA_STATE_DB | 本目录 runtime/state.sqlite | 网页和后台共享的 SQLite 状态库 |
| TA_HOST、TA_PORT | 127.0.0.1、8765 | 本地网页监听地址、端口 |
| TA_OBSERVE_ONLY | 0 | 0 为买卖提醒及虚拟交易触发模式；1 为观察模式 |
| TA_QUOTE_INTERVAL | 3 | 腾讯批量轮询间隔，单位秒 |
| TA_QUOTE_TIMEOUT | 2 | 单次行情请求超时，单位秒 |
| TA_MAX_QUOTE_AGE | 10 | 报价最大年龄，单位秒；交易日验证后调整 |

PowerShell 示例：

~~~powershell
$env:TA_MARKET_DB = "D:\market-data\market_full.duckdb"
$env:TA_STATE_DB = "D:\market-data\assistant-state.sqlite"
python run.py worker
~~~

两个虚拟账户分别记账，稳健盘默认本金 100 万元，激进盘固定从 100 万元开始；普通日每单预算 7.5 万元，候选总数达到 50 只时前五名单每单固定 20 万元。两盘使用相同的费用参数：单边佣金 0.025%、最低 5 元、默认过户费与卖出印花税、零滑点。价格条件触发后，虚拟盘默认委托成功，不以买一卖一深度阻断成交；资金不足、停牌、ST、异常报价和公司行为核对仍可能阻断。实盘不设置初始本金、模拟账户净值或盈亏统计，只记录人工确认的提醒状态和提醒价。网页虚拟盘参数调整从下一日生效，已有虚拟持仓保留原参数版本。运行成交模型与此前日线回测不同，历史收益不能直接套用。

## 双策略启用与更新

稳健盘沿用原虚拟盘历史；激进盘从新版本启用后的首个未发布交易日开始独立记账，期初本金 100 万元。两盘共用前五名选股、买点、费用及 7.5 万／20 万元单笔预算；稳健盘深跌组首次目标在候选数达到 50 只时为 10%，否则为 8%；激进盘深跌组不首次减仓，其余股票均使用 1% 首次目标。实盘切换在交易日 09:30—15:00（含午休）由服务器拒绝，其他时间切换立即生效，并同步更新当天尚未触发买入的实盘计划；已有持仓保留原退出规则。升级时若数据库有旧版未生效的预约，会将最后一次预约的策略立即设为当前策略并清除未来预约。顶部指数行情独立于交易报价健康判断。

已有数据库在启动时自动迁移，无须重新初始化或迁移市场行情；部署更新前请使用 `bash deploy/manage.sh update` 自带的备份流程，并选择非交易时段更新。部署后，当前交易日已经发布的名单不追溯重算；待下一个盘前发布新名单时才开始两盘同时执行。

## 自动流程

后台每天更新交易日历。交易日 08:00 至 09:20 自动检查并补齐前一已完成交易日的日线、逐日 ST、停牌缺口、异常成交量及最近三年质量；通过后将符合超跌和 ATR 条件的股票按**过去 20 个有效交易日的每日成交额中位数从高到低**排序，成交额相同再按 5 日跌幅最接近 −12%、股票代码升序排序。只发布前 5 名供两盘使用；虚拟盘另行预留预算。第 6 名及以后不发布重点关注，也不监听。数据不完整时暂停新买入，后台继续重试。15:00 结束当日观察并释放未触发预留；15:30 后自动同步当天日线并归档前 5 只候选股和持仓股的当日 1 分钟线。

历史日线增量优先直接调用腾讯接口，每只股票抓原始与前复权两组数据，正常情况下只更新最近约三周；停机造成更长缺口时自动扩展查询窗口，未覆盖的历史缺口再由 BaoStock 核对补齐。腾讯失败时才串行尝试新浪接口。新浪历史日线调用的本地 V8 解码库不适合多线程同时初始化，不能将其作为并发主源。

买点是“开盘价高于限价、有效盘中快照低于限价至少 0.01 元”。前五名的实盘买点独立提醒；即使两个虚拟盘资金不足或已有同股持仓，实盘提醒仍可出现。虚拟盘有资金且满足规则时即按限价记虚拟买入，不核查对手盘数量；虚拟止盈止损也按触发价或有效快照价记账。实盘页分为“信号”“当前持仓”“操作记录”“历史持仓”“设置”五个子页；策略切换位于“设置”，操作记录和历史持仓均分页。实盘由用户在券商端操作，再在对应提醒上点击“已完成”或“跳过”。买入“已完成”后，以提醒中冻结的价格建立系统托管状态，并据此计算止盈止损；买入“跳过”后不建立持仓。需要首次止盈的持仓“已完成”后跟踪余仓退出线；激进深跌持仓不首次减仓，只监听初始止损与持仓到期。清仓“已完成”后结束监控。任一卖出提醒“跳过”后，持仓改为“用户自行操作”，不再自动生成卖出提醒；用户自行清仓后可在持仓列表点击“已自行清仓”。实盘不要求录入股数，也不计算实际盈亏。

异常报价、时间戳过旧、ST、停牌和公司行为未核对时停止相关虚拟成交，并在页面给出原因。虚拟代理成交不等于券商成交；实盘记录的是提醒价和用户确认的操作阶段，不代表券商实际成交价。系统不会依据事后的日最低/最高价补造当时没观察到的买卖。

## 手工维护命令

~~~powershell
python run.py status
python run.py sync --date 2026-10-09
python run.py preopen --date 2026-10-12
python -m pytest -q
~~~

日常运行不需要手工执行 sync 或 preopen；这些命令用于诊断和补救。不要在后台工作进程运行时并行执行会写 DuckDB 的命令，因为普通 DuckDB 文件只允许一个读写进程。网页进程只读写 SQLite，不直接打开市场库。

## 数据与备份

- runtime/state.sqlite 保存设置、观察名单、指数行情、两个虚拟交易账本、实盘策略切换和提醒状态、事件日志；按本机 SQLite 备份 API 备份，不要只复制运行中的主文件而遗漏 WAL。
- 市场库保存全市场日线、交易日历、缺口分类和按需一分钟线。将它复制到服务器时需停掉后台写入进程。
- 免费腾讯/新浪网页接口没有服务等级承诺；交易时段结果、数据用途与稳定性仍须核验。交易受阻或实际成交价差异需以券商记录为准。

## 当前实现边界

公司行为会阻断相关股票的虚拟卖出并提示人工核对，暂未自动重建分红送转现金与股数。免费行情源可能缺报或延迟；相关股票在没有有效报价时不会产生买卖提醒。实际成交和手续费须以券商记录为准。
